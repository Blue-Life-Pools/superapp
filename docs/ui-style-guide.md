# BlueLife dashboard visual direction

The user approved the visual direction in the “BlueLife Report History Dashboard” and “Streamlined Field Service Dashboard” references. Use the implemented Reports and Quality panels as examples for future interface work.

- Use white surfaces, thin neutral borders (`#dfe5ef`), restrained shadows and rounded corners around 10–14 px. Avoid large tinted backgrounds and overlapping panels.
- Use dark navy text (`#111b34`) and blue primary actions (`#0866ff`). Reserve orange, green, violet, red and amber for meaningful metric or status accents.
- Use the application's existing font family. Typical desktop sizes are 28–30 px for page titles, 19–23 px for section titles, 12–14 px for labels and content, and 28–32 px for metric values. Avoid oversized titles, heavy text throughout or distorted SVG text.
- Put a small blue eyebrow above the title and a short description below it. Align primary actions at the right. Omit extra BlueLife logos from content headers; retain the shared application navigation.
- Show one row of metrics with aligned outline icons. Where metrics are filters, use real buttons with a visible selected state.
- Align primary filters in a compact toolbar. Keep search and secondary filters available without duplicating large control panels. Label filters accessibly.
- Put secondary record actions in an accessible three-dot menu. Keep status selectors and frequently used navigation visible. Menus must escape scroll containers without being cut off.
- For list/detail workspaces, align the list and selected detail at the top. Keep record names, dates and selection states readable. Use compact status pills and photo thumbnails with full previews.
- Keep original calculations, permissions, editing fields, dates, audits and attachments. Display pagination must not change totals or the records included in an export.
- Adapt columns and controls to available width, checking both expanded and collapsed navigation. Prevent text, cards and floating controls from overlapping. Use horizontal navigation for long strips of readings rather than squeezing values.

Apply this direction to the requested scope; do not restyle unrelated panels automatically.
